# Implementation Plan: Harness v1.9 Hardening & Compliance Upgrade

> **Goal:** Address the 4 structural gaps in the OpenCode SaaS Kit harness to achieve 10/10 production-grade determinism: (1) Atomic `_workspace/harness-state.json` State Machine, (2) Semantic & AST/Token-Aware Security & Task Sizing (`triage-sizer.mjs` + `pre-tool-guard.mjs`), (3) SSoT-Safe Active Pack Projection (`skill-pack-manager.mjs` + `sync-kit.mjs`), and (4) Behavioral Compliance Evaluation Suite (`eval-harness.mjs` with HCI scoring).
>
> **Architecture:** Single Source of Truth (`.agent-core/`) and CLI (`scripts/`, `bin/cli.js`) expansion. Zero breaking changes to existing 14 agents, 9 commands, and 326 skills. All enhancements are enforced via deterministic Node.js modules with 100% unit/integration test coverage (`node:test`) and synchronized across OpenCode, Claude Code, Antigravity, and Codex via `scripts/sync-kit.mjs`.
>
> **Tech Stack:** Node.js (>= 18.0.0, zero external runtime dependencies), JSON Schema / FSM state management, shell token parser, Vitest / `node:test`.

---

## Global Constraints

1. **SSoT Preservation:** `.agent-core/` is the immutable Single Source of Truth for the kit. Pack activation/deactivation MUST NEVER delete files inside `.agent-core/`; instead, active packs are projected into harness adapters (`.opencode/`, `.agents/`, `.claude/`) or filtered in `agent-registry.json`.
2. **Zero External Runtime Dependencies:** All new scripts in `scripts/` and `.agent-core/hooks/` must use pure Node.js built-ins (`fs`, `path`, `crypto`, `child_process`) so `npx opencode-saas-kit` runs out-of-the-box anywhere.
3. **Strict TDD (RED → GREEN → REFACTOR):** Every task begins by writing failing tests in `scripts/__tests__/*.test.mjs`, followed by minimal implementation to pass, then refactoring.
4. **Backward Compatibility:** Existing CLI invocations (`npx opencode-saas-kit init|sync|verify|pack`) and slash commands (`/plan`, `/build`, `/review`, `/ship`, `/hotfix`) remain 100% compatible.

## Workstream 2: Semantic Risk-Aware Task Sizing & Hardened Runtime Guard

**Problem:**
1. `triage-sizer.mjs` uses character length (`< 120` chars) and basic keywords, misclassifying short high-risk prompts (e.g., *"Add OAuth2 login"*, *"Change JWT secret rotation"*, *"Drop legacy users column"*) as Size S or M instead of escalating to Size M/L.
2. `pre-tool-guard.mjs` misses command obfuscation, subshells (`$(cat .env)`), inline scripting (`node -e`, `python -c` reading `.env`), encoding dumps (`base64 .env`), and git history destruction (`git push --force origin main`, `git commit --no-verify`).

- Modify: `scripts/triage-sizer.mjs`

  - Add test cases for short high-risk prompts:
    - `"Add OAuth2 login"` → Must escalate to at least Size `M` or `L` (never `S`), flagging `riskFlags: ['auth-security']`.
    - `"Add Stripe webhook signature check"` → Size `M` (single endpoint/webhook) with mandatory security review prerequisite.
    - `"Run database migration to drop column"` → Escalate away from `S` due to `riskFlags: ['db-migration']`.

  - Block Size `S` whenever `riskFlags.length > 0` (unless explicitly matched as cosmetic copy/style tweak).
